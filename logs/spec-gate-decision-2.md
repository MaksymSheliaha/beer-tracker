## 1. Audit Criteria Verification

### 1.1. Несуперечність (Consistency)
* **Усунуто архітектурний конфлікт незмінності:**
  * У Розділі 2.3 (п. 2), REQ-F-012 та REQ-NF-010 чітко розмежовано рівні доступу до бази даних: стандартний пул застосунку обмежено суворо правами `INSERT` та `SELECT`, а операція каскадного оновлення зовнішніх ключів на `Tombstone` виконується ізольовано через збережену процедуру з правами `SECURITY DEFINER`.
* **Виправлено діаграму станів консенсусу (Розділ 4.2):**
  * Перехід чернетки редагування при $\ge 5$ голосах `DOWNVOTE` тепер коректно веде у фінальний стан завершення `[*]`, а попередня верифікована версія залишається активною.
* **Закрито функціональну неповноту життєвого циклу:**
  * Додано вимогу `REQ-F-013: Product Draft Submission for Existing Product Edits` та REST API маршрут `PUT /api/v1/products/{id}/draft`.
  * Додано вимогу `REQ-F-014: Manual Wishlist Management` та REST API маршрути `POST` і `DELETE /api/v1/users/me/wishlist`.
* **Усунуто невизначеність офлайн-відновлення:**
  * У REQ-F-007 (AC-007.2) та на Діаграмі 4.3 чітко зафіксовано, що буфер Soft-Undo діє виключно для онлайну (60 секунд), тоді як накопичена офлайн-черга передається на сервер негайно за порядком FIFO після відновлення зв'язку.

### 1.2. Тестованість (Testability)
* **Регламентовано розв'язання гонитви (Race Condition):**
  * У REQ-F-003 (AC-003.5) зафіксовано використання песимістичного блокування рядків `SELECT FOR UPDATE` за принципом First-Commit Wins; спроби голосування після фіксації результату відхиляються з HTTP 409 Conflict.
* **Детерміновано правила Tie-Breaking:**
  * У REQ-F-011 (AC-011.3) введено чітке вторинне сортування за часом останнього споживання (`last_consumed_at DESC`).
* **Зафіксовано валідацію часових поясів:**
  * У REQ-F-010 (AC-010.4) регламентовано повернення HTTP 400 Bad Request при невідомому IANA-ідентифікаторі. Додано BDD-сценарій `BDD-SCN-006`.

### 1.3. Відсутність невизначених термінів (Glossary Compliance)
* **Повна відповідність Domain Glossary:**
  * Проведено очищення тексту специфікації від заборонених синонімів (`item`, `intake`, `rollback`, `spam`, `stars`). Усі сутності узгоджено з канонічною термінологією.
* **Повнота визначень у глосарії:**
  * Розділ 1.3 доповнено визначеннями термінів та скорочень `ABV`, `CAPTCHA` та `EAN-13 / UPC`.

### 1.4. Реалістичність критеріїв прийняття (Acceptance Criteria)
* **Повнота критеріїв валідації відгуків:**
  * Додано критерій AC-009.4, що обмежує розмір коментаря до 2000 UTF-8 символів та повертає HTTP 400 у разі перевищення.
* **Покриття матрицею простежуваності:**
  * Усі нові вимоги (REQ-F-013, REQ-F-014), а також оновлені критерії прийняття та сценарії внесені до `spec/traceability-matrix.md`.
