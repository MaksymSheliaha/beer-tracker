## 1. Обґрунтування зміни (Business & Domain Rationale)

Користувачам платформи **Beer Tracker** під час пошуку напоїв у каталозі (`GET /api/v1/beers`) часто потрібно відбирати сорти пива за діапазоном міцності (`ABV` — Alcohol by Volume, %), наприклад:
- безалкогольні та легкі столові сорти (`0.0% .. 4.5%`);
- класичні елі та лагери (`4.5% .. 6.5%`);
- міцні імперські стаути та барлівайни (`8.0% .. 15.0%`).

Додавання необов'язкових query-параметрів `min_abv` та `max_abv` до операції `GET /api/v1/beers` є **зворотно сумісним (backward-compatible)** розширенням контракту OpenAPI 3.0.3 та не порушує жодного існуючого сценарію клієнтів.

## 2. Специфікація вимоги `REQ-F-015`

### REQ-F-015: Фільтрація каталогу пива за діапазоном міцності (`min_abv`, `max_abv`)
Система повинна підтримувати фільтрацію активних продуктів каталогу в операції `GET /api/v1/beers` за мінімальним (`min_abv`) та/або максимальним (`max_abv`) вмістом алкоголю за об'ємом (`abv`, у відсотках `[0.0 .. 100.0]`).

#### Критерії приймання (Acceptance Criteria):
- **AC-015.1 (Включна фільтрація за діапазоном):**
  - Якщо передано параметр `min_abv`, у вибірку включаються лише продукти, для яких `beer.abv >= min_abv`.
  - Якщо передано параметр `max_abv`, у вибірку включаються лише продукти, для яких `beer.abv <= max_abv`.
  - Якщо передано обидва параметри (`min_abv` та `max_abv`), повертаються лише продукти, що задовольняють умову `min_abv <= beer.abv <= max_abv` одночасно з іншими активними фільтрами (`query` тощо).
- **AC-015.2 (Валідація меж та інверсії діапазону):**
  - Значення `min_abv` та `max_abv` мають перебувати в допустимих межах `[0.0 .. 100.0]`.
  - Якщо `min_abv < 0.0`, `max_abv > 100.0` або `min_abv > max_abv` (інвертований діапазон), сервер відхиляє запит зі статусом `400 Bad Request` (`code: INVALID_ABV_RANGE`) та деталізацією проблемного параметра в `ErrorResponse`.

## 3. BDD Сценарій приймання (`BDD-SCN-006`)

```gherkin
Feature: Фільтрація каталогу пива за вмістом алкоголю (REQ-F-015)

  Scenario: BDD-SCN-006 Успішна фільтрація каталогу за діапазоном міцності [min_abv, max_abv] та відхилення невалідного діапазону
    Given у каталозі зареєстровано три сорти пива:
      | name                     | brewery           | abv  | barcode       |
      | Light Session IPA        | Varvar            | 3.8  | 4820777000011 |
      | Mova Classic Stout       | Mova Brewing Co.  | 5.8  | 4820777000012 |
      | Imperial Baltic Porter   | Pravda            | 9.5  | 4820777000013 |
    When клієнт виконує запит GET "/api/v1/beers?min_abv=5.0&max_abv=8.0"
    Then сервер повертає статус 200 OK
    And список "items" містить рівно 1 продукт із назвою "Mova Classic Stout" та abv 5.8
    When клієнт виконує запит із інвертованим діапазоном GET "/api/v1/beers?min_abv=8.0&max_abv=4.0"
    Then сервер повертає статус 400 Bad Request із кодом помилки "INVALID_ABV_RANGE"
```
